# 目标分配问题：数学描述与低计算量算法调研

> 场景：\(m\) 个智能体、\(n\) 个目标；每个智能体每步只选 1 个目标；已知行随机的倾向矩阵 \(S\)；目标为最大化总倾向分。调研限定在“计算量小、可实时或可分布式”的算法，并明确区分互斥（一个目标最多给一个智能体）与非互斥（允许多个智能体选择同一目标）。

## 0. 速览

| 场景 | 首选算法 | 典型复杂度 | 最优性 |
| --- | --- | --- | --- |
| 非互斥、目标无容量 | 逐行 `argmax` | \(O(mn)\) | 全局最优 |
| 互斥、\(m,n\le\) 几十 | Hungarian / Jonker-Volgenant | \(O(m^2n)\)，方阵 \(O(n^3)\) | 精确 |
| 互斥、大规模稀疏 | 拍卖算法（\(\varepsilon\)-缩放） | 约 \(O(|E|\log(nC))\) | \(\varepsilon\)-最优，缩放到足够小可视为精确 |
| 需要可微 / GPU 批处理 | Sinkhorn | 每轮 \(O(mn)\) | 熵正则近似 + 舍入 |
| 无中心节点、通信受限 | 分布式拍卖 / CBBA | 有限轮消息传递 | \(\varepsilon\)-最优 / 50% 保证 |
| 目标有容量或需覆盖 | 最小费用流 / 带容量拍卖 | 多项式 | 精确（线性目标） |
| 一般化武器-目标分配（多资源协同） | 贪心、拍卖、CBBA、元启发式 | NP-hard | 近似 |

一句话结论：

- **非互斥且无容量约束时，问题按行完全可分离**，逐行取最大就是全局最优，\(O(mn)\) 且不需要任何通信；这是该类问题的“计算下界”。
- **互斥时就是带权二分图匹配（线性分配问题 LAP）**，多项式可解；本项目的 \(2v2/4v4/10v10\) 规模用中心式 Hungarian 的耗时可忽略。
- **加入目标容量、覆盖（每个目标至少一个智能体）、多资源协同等约束后，一般化 WTA 是 NP-hard**，此时才需要贪心、拍卖、CBBA 等近似算法。
- **分布式算法的主要开销在“价格/列和”这类全局量的共识上**；若存在可信中心节点，中心式 Hungarian 往往比分布式更省算力、更稳定。

## 1. 数学描述

### 1.1 符号

- 智能体集合 \(\mathcal I=\{1,\dots,m\}\)，目标集合 \(\mathcal J=\{1,\dots,n\}\)。
- 倾向矩阵 \(S=[S_{ij}]\in(0,1)^{m\times n}\)，行随机：
  \[
  \sum_{j=1}^{n} S_{ij}=1,\qquad \forall i\in\mathcal I .
  \]
- 分配矩阵 \(A=[A_{ij}]\in\{0,1\}^{m\times n}\)，每个智能体恰好选一个目标：
  \[
  \sum_{j=1}^{n} A_{ij}=1,\qquad \forall i\in\mathcal I .
  \]
- 分配索引向量 \(b=(b_1,\dots,b_m)\)，其中 \(b_i\in\mathcal J\)，且
  \[
  A_{ij}=\mathbb 1[b_i=j],\qquad b_i=\sum_{j=1}^{n} j\,A_{ij}.
  \]

\(A\) 与 \(b\) 等价，\(A\) 是 \(b\) 的 one-hot 展开；实际存储和传递只需要 \(b\)。

### 1.2 目标函数

\[
\max_{A}\; J(A)=\sum_{i=1}^{m}\sum_{j=1}^{n} S_{ij}A_{ij}
=\sum_{i=1}^{m} S_{i,b_i}.
\]

等价地，直接在索引向量上优化：

\[
\max_{b\in\{1,\dots,n\}^m}\; \sum_{i=1}^{m} S_{i,b_i}.
\]

若互斥，则附加

\[
b_i\neq b_k,\qquad \forall i\neq k,
\]

即

\[
\sum_{i=1}^{m} A_{ij}\le 1,\qquad \forall j\in\mathcal J.
\]

### 1.3 常见约束变体

| 变体 | 约束 | 说明 |
| --- | --- | --- |
| 互斥（一对一匹配） | \(\sum_i A_{ij}\le 1\) | \(m\le n\) 才可行；\(m=n\) 时是置换 |
| 非互斥（多对一） | 无列约束 | 多个智能体可打同一目标 |
| 目标容量 | \(\sum_i A_{ij}\le c_j\) | 每个目标最多接收 \(c_j\) 个智能体 |
| 覆盖 | \(\sum_i A_{ij}\ge 1\) | 每个目标至少一个智能体；\(m\ge n\) 才可行 |
| 每智能体多目标 | \(\sum_j A_{ij}\le k_i\) | 智能体可携带多个目标/武器 |
| 空闲/放弃 | 增加虚拟目标 \(j=0\)，\(S_{i0}=\) 阈值 | 行和可放宽为 \(0\) 或 \(1\) |
| 动态 | \(S=S(t)\)，目标/智能体数量变化 | 需要增量或 anytime 算法 |

若 \(m>n\) 且要求互斥，则不可能让所有智能体都分到不同目标；此时应选择：允许多对一、增加目标容量 \(\lceil m/n\rceil\)、或允许部分智能体空闲。若 \(m<n\) 且要求覆盖所有目标，同样不可行。

### 1.4 结构性质

**（1）线性分配问题是 LP，且 LP 松弛是紧的。** 去掉 \(A_{ij}\in\{0,1\}\) 后：

\[
\max_{A\ge 0}\; \sum_{ij}S_{ij}A_{ij}
\quad\text{s.t.}\quad
\sum_j A_{ij}=1,\;\; \sum_i A_{ij}\le 1 .
\]

约束矩阵是全幺模（TU）的，因此 LP 的最优顶点自动是 0/1 矩阵；整数规划与 LP 同解。这正是 Hungarian、拍卖、最小费用流都能精确求解的原因。

**（2）等价于最小费用流。** 建图：源点 \(\to\) 每个智能体（容量 1，费用 0）；智能体 \(i\to\) 目标 \(j\)（容量 1，费用 \(-S_{ij}\)）；目标 \(\to\) 汇点（容量 1，费用 0）。发送 \(m\) 单位流即可。带容量 \(c_j\) 时只需把目标到汇点的容量改成 \(c_j\)。

**（3）对偶与互补松弛。** 对偶为

\[
\min_{u,v}\; \sum_i u_i+\sum_j v_j
\quad\text{s.t.}\quad
u_i+v_j\ge S_{ij},\;\; v_j\ge 0 .
\]

互补松弛条件：若 \(A_{ij}=1\)，则 \(u_i+v_j=S_{ij}\)。Hungarian 的势函数、拍卖的价格、BP 的消息都可以看作对这组对偶变量的不同维护方式。

**（4）行随机归一化不影响最优解。** 对任意一行加上常数 \(c_i\)，目标值只增加 \(\sum_i c_i\)，不改变最优 \(b\)。因此 \(S\) 是否按行归一化、是否用 softmax，对分配决策本身没有影响；归一化主要用于解释为概率。若真正想最大化“联合似然” \(\prod_i S_{i,b_i}\)，则应优化 \(\sum_i \log S_{i,b_i}\)，这是另一个目标（仍然是逐行可分离的，但不再等价于最大化概率和）。

**（5）互斥匹配的近似下界。** 任意极大匹配（包括贪心得到的匹配）的权重至少是最优匹配的 \(1/2\)；这是贪心类算法最常用的最坏保证。

### 1.5 可解性一览

- 非互斥、无容量：逐行独立，\(O(mn)\)，精确。
- 互斥一对一：LAP，多项式精确；稠密 Hungarian \(O(m^2n)\)，JV \(O(n^3)\)。
- 目标容量 / 覆盖（列和上下界）：线性费用下仍是最小费用流，多项式精确；带上下界时用带下界的流或两阶段处理。
- 每智能体可带多个目标且目标可共享：变成带划分拟阵约束的分配/子模最大化；一般情形 NP-hard，贪心有 \(1/2\) 保证。
- 异构资源、协同毁伤、多波次等一般化 WTA：NP-hard，通常只能近似或元启发式。

## 2. 互斥（一对一）算法

### 2.1 Hungarian / Jonker-Volgenant（中心式、精确）

**思路**：维护行势 \(u_i\)、列势 \(v_j\)，在相等子图（\(u_i+v_j=S_{ij}\)）上不断找增广路；每找到一条增广路就扩大匹配，直到所有行都匹配。这就是原始-对偶形式的 LAP 求解。

- 复杂度：\(O(m^2n)\)（\(m\le n\)）；方阵 \(O(n^3)\)。
- 优点：精确、稳定、实现成熟；\(m,n\le 100\) 时通常远快于理论上界。
- 缺点：需要集中式拿到完整 \(S\)；动态场景若每步从头算，重复计算多。
- 工程要点：
  - 最大化转为最小化：费用取 \(-S\)；
  - 矩形矩阵补虚拟列/行（虚拟分数设 0 或阈值）；
  - 平局用微小扰动或字典序打破，保证可复现；
  - 动态场景可**热启动**：上一步的匹配和势作为初值，只对变化的部分做增广，通常只需少量增广路。

**Jonker-Volgenant（JV）** 是最短增广路实现的经典版本，最坏 \(O(n^3)\)，但常数和实际速度通常明显优于朴素 Hungarian，是很多工程库（如 `scipy.optimize.linear_sum_assignment`）的默认选择。

### 2.2 拍卖算法（Auction，中心式/并行/可分布式）

**思路**：把目标看作商品，智能体对目标出价，目标价格 \(p_j\) 上涨；智能体总是争取当前“净收益” \(S_{ij}-p_j\) 最大的目标。核心是 \(\varepsilon\)-互补松弛（\(\varepsilon\)-CS）：

> 每个已分配智能体对其目标的净收益，与它可选的任何其他目标的净收益之差不超过 \(\varepsilon\)。

简化流程：

```text
p_j ← 0
while 存在未分配的智能体:
    选一个未分配智能体 i
    j1 ← argmax_j (S_ij - p_j)
    j2 ← argmax_{j≠j1} (S_ij - p_j)
    δ  ← (S_ij1 - p_j1) - (S_ij2 - p_j2) + ε
    p_j1 ← p_j1 + δ
    if j1 已被 k 占有: 取消 k 的分配
    把 i 分配给 j1
```

- 复杂度：采用 aggressive \(\varepsilon\)-scaling 时约为 \(O(|E|\log(nC))\)，其中 \(|E|\) 是可分配弧数、\(C\) 是分值范围；实际运行通常接近线性。
- 特点：**anytime**（随时截断都能给出可行解）、天然并行（Jacobi 版本可同时出价）、易加容量约束、易分布式化。
- 精度：\(\varepsilon\)-最优（总误差至多 \(m\varepsilon\)）；\(\varepsilon\)-缩放（从大 \(\varepsilon\) 逐步减小）可在整数费用下恢复精确解；连续分数下取足够小的 \(\varepsilon\) 即可。
- 适用：大规模稀疏、实时性要求高、需要早停、或没有中心求解器的场景。

### 2.3 Sinkhorn（熵正则、可微、GPU 友好）

把互斥分配放松为“双随机矩阵”上的熵正则最优传输：

\[
\max_{P\in U}\; \sum_{ij}S_{ij}P_{ij}+\tau H(P),
\]

其中 \(U\) 是行和/列和约束下的传输多面体，\(H(P)=-\sum_{ij}P_{ij}\log P_{ij}\)，\(\tau>0\) 是温度。令 \(K_{ij}=\exp(S_{ij}/\tau)\)，交替做行、列归一化：

```text
v ← 1
repeat:
    u ← 1 / (K v)          # 行归一化
    v ← 1 / (K^T u)        # 列归一化
until 收敛
P = diag(u) K diag(v)
```

- 每轮 \(O(mn)\)；有近线性时间的近似保证；GPU 上可批量处理。
- \(\tau\to 0\) 时 \(P\) 趋向置换矩阵，但数值上需要退火；最后还要**舍入**（对 \(P\) 做贪心舍入，或把 \(P\) 当作费用再跑一次 Hungarian）才能得到严格可行的 \(b\)。
- 优点：可微，适合“策略网络输出 \(S\) → 端到端训练分配层”的 MARL 场景；也有 Gumbel-Sinkhorn 这类可微置换采样版本。
- 缺点：熵正则带来偏差，不是精确 LAP；\(\tau\) 太小会数值不稳，太大则解过于“软”。
- 矩形情形：把矩阵补齐为方阵（虚拟智能体/虚拟目标分数设 0），或使用部分最优传输。

### 2.4 Max-product 置信传播（BP，消息传递/分布式）

在“智能体—目标”二分图上做最大积消息传递，等价于在 LAP 的 LP 对偶上做坐标上升。

- 每轮 \(O(|E|)\)，\(|E|\) 为非零/可分配边数；稀疏图上很省。
- 收敛性：若 LAP 的 LP 松弛是紧的且最优解唯一，max-product 收敛到最优匹配；迭代次数约 \(O(n\,w_{\max}/\varepsilon)\)。若 LP 不紧（存在对偶间隙），BP 可能振荡。
- 优点：天然分布式、消息局部；适合稀疏大图、多目标跟踪中的数据关联。
- 缺点：稠密图消息量大；需要阻尼/退火等工程技巧。

### 2.5 贪心 + 2-opt（最轻量的基线）

**全局贪心**：把所有 \((i,j)\) 按 \(S_{ij}\) 降序排序，依次分配，若智能体空闲且目标空闲则接受。

- 复杂度：\(O(mn\log(mn))\)。
- 保证：极大匹配，权重 \(\ge \frac12\) 最优；实现极简、可解释、易分布式近似。

**2-opt 局部搜索**：对任意两个已分配智能体 \(i,k\)，若

\[
S_{i,b_k}+S_{k,b_i} > S_{i,b_i}+S_{k,b_k},
\]

则交换二者目标。一次扫描 \(O(m^2)\)，可重复到无改进。

- 通常显著优于纯贪心；最坏仍只有 \(1/2\) 保证（因为它仍是极大匹配）。
- 可作为 Hungarian 的热启动、或超大规模时的 anytime 近似。

### 2.6 代价缩放 / 网络单纯形（大规模稀疏精确）

把 LAP 看成最小费用流，用代价缩放（cost-scaling）或网络单纯形求解。

- 多项式时间；稀疏大图上的实际性能通常优于稠密 Hungarian。
- 适合 \(m,n\) 上千、边稀疏、需要精确解的场景；实现复杂度较高，通常直接调用现成求解器。

## 3. 非互斥算法

### 3.1 逐行 argmax（精确、零通信）

无列约束时目标函数按行可分离：

\[
b_i^\* \in \arg\max_{j\in\mathcal J} S_{ij},\qquad \forall i.
\]

- 复杂度 \(O(mn)\)，每个智能体只需自己的行，完全分布式、零通信。
- 平局处理：按距离/威胁优先级/编号做二级排序；或随机打破以保证公平。
- 若智能体看不到全部目标，可用 **max-consensus** 在通信图上求全局最大值，轮数与图直径相关；或者只在自己可见的目标集合上取最大（会损失最优性）。

这是“非互斥”场景的基准：任何互斥算法若强行让某些智能体放弃其最大目标，都会损失一部分总倾向分；是否值得，取决于任务语义（例如是否允许重复打击）。

### 3.2 有目标容量 \(c_j\)

约束变为 \(\sum_i A_{ij}\le c_j\)。仍是线性费用的运输问题：

- **最小费用流**：目标到汇点容量改为 \(c_j\)，精确，多项式。
- **带容量拍卖**：每个目标保留净收益最高的至多 \(c_j\) 个出价，价格由竞争产生；是运输问题拍卖算法的直接扩展。
- **容量 Sinkhorn**：列和改为 \(c_j\)（需总容量 \(\sum_j c_j\ge m\)），每轮 \(O(mn)\)。
- **容量贪心**：按 \(S\) 降序填充，智能体空闲且目标未满则分配；\(O(mn\log(mn))\)，不保证最优，但很快。

若 \(m>n\) 且每个目标容量为 \(\lceil m/n\rceil\)，容量模型可以自然处理“必须全部智能体都有目标”的互斥不可行情形。

### 3.3 覆盖约束（每个目标至少一个智能体）

约束为 \(\sum_i A_{ij}\ge 1\)（\(m\ge n\)）。这是带下界的流问题：

- 最小费用流 + 列下界，线性费用下多项式精确；可行时自动满足覆盖。
- 工程上常用的两阶段：先做一次“覆盖匹配”（把每个目标至少配一个智能体，可用 Hungarian 或贪心），剩余智能体再逐行 argmax；两阶段不保证全局最优，但简单可控。
- 若同时要求互斥且覆盖，则必须 \(m=n\)，退化为置换匹配。

### 3.4 目标存在拥塞/边际收益递减（子模）

如果多个智能体打同一目标会降低边际价值（例如毁伤饱和、重复拦截浪费），目标函数不再是线性的 \(\sum_i S_{i,b_i}\)，而是单调子模函数。此时：

- 一般问题是 NP-hard；
- 在划分拟阵约束（每个智能体选一个）下，**贪心**有 \(1/2\) 近似保证；CBBA 的 50% 保证也来自这一类假设；
- 若约束是基数约束而非拟阵，则有 \(1-1/e\) 的经典保证；分配场景通常更接近前者。

### 3.5 随机/可微分配（探索与训练）

- 每个智能体按 \(S_i\) 独立采样（多项式/softmax 采样），\(O(mn)\)；碰撞可按优先级重采样，或允许重复（非互斥）。
- 若需要“无放回”的联合采样，精确按 \(\exp(\sum_i S_{i,b_i})\) 采样涉及矩阵永久值（#P-hard）；工程上用 Gumbel-Sinkhorn 近似，或用“先 Sinkhorn 再舍入/采样”。
- Gumbel-top-k 可用于每个智能体保留前 \(k\) 个候选，再做局部协商；它本身不是全局无放回分配算法，但计算很轻。

## 4. 分布式算法

### 4.1 分布式拍卖（Zavlanos et al., 2008）

每个智能体维护本地价格/出价，只与通信邻居交换价格信息；通过价格共识替代中心拍卖师。特点：

- 有限步收敛到 \(\varepsilon\)-最优分配，需通信图连通；
- 支持目标/智能体动态加入退出；
- 通信量主要是价格向量的交换，通常远小于传输完整 \(S\) 矩阵；
- 与中心式拍卖同样的 \(\varepsilon\)-CS 保证，但收敛速度受图直径和价格竞争影响。

### 4.2 CBBA（Consensus-Based Bundle Algorithm，Choi et al., 2009）

两阶段：

1. **bundle building**：每个智能体按边际收益贪心地把目标加入自己的任务包；
2. **consensus**：邻居间比较“谁对哪个目标出价更高”，输者移除该目标并重建包。

特点：

- 对单调子模/边际收益递减的效用，给出 **50% 最优性保证**；
- 有限轮收敛（与通信图/智能体数相关），支持动态任务；
- 在线性互斥场景下，每个智能体的包只有一个目标，CBBA 更接近“分布式贪心 + 冲突消解”，不保证 LAP 精确最优；
- 通信是邻居间的任务/出价表，适合无中心、通信受限的集群。

### 4.3 分布式/去中心化 Sinkhorn

中心式 Sinkhorn 的行归一化是局部的，但列归一化需要全局列和。分布式做法：

- 每个智能体本地做行归一化；
- 用 gossip/consensus 在邻域内传播列消息（log 域求和/平均），近似全局列和；
- 交替“本地更新 + 共识轮”，收敛到中心式 Sinkhorn 的近似解。

通信量与精度可折中（事件触发、量化、稀疏 gossip）。适合需要可微/概率化分配、且没有中心聚合器的场景。

### 4.4 分布式 ADMM / 原始-对偶

按智能体行分块，引入列和一致性约束（或价格一致性），用 ADMM/对偶分解迭代：

- 每轮每个智能体解一个小规模局部 LAP（或线性子问题），再对价格/列和做共识；
- 可收敛到精确 LAP 解（到容差），但通信轮数通常多于拍卖；
- 适合有较强计算能力、通信相对可靠、追求精确性的分布式系统。

### 4.5 势博弈 / 最优响应 / 学习型协调

把每个智能体的净收益写成 \(S_{i,b_i}-p_{b_i}\)，则拍卖类过程可视为势博弈的最优响应，势函数与社会总福利对齐；配合价格机制可收敛到（近似）最优。

若智能体只最大化自己的 \(S_{i,b_i}\) 而不引入价格/冲突消解，纯自利最优响应可能停在低效的 Nash 均衡（例如两个智能体争抢同一目标、另一些目标空置）。因此：

- 有价格/投标机制：可作为分布式拍卖的博弈解释；
- 无价格机制：只能得到局部/均衡解，不能保证全局最优；
- 学习型方法（MARL、图神经网络）计算量通常更大，不属于“低计算量”首选。

## 6. 针对本项目的选型建议

本项目是 \(2v2/4v4/10v10\) 量级的多机空战 RL，单步决策的 \(m,n\) 都很小。建议按以下顺序决策：

1. **先确认语义：目标是否允许被多个智能体同时选择。**
   - 允许（例如多机协同压制/多枚导弹拦截同一威胁）：直接逐行 `argmax`，\(O(mn)\)，保留策略语义，无需引入分配层；若要探索，用逐行采样。
   - 不允许（一个目标只应由一个智能体主攻）：用 Hungarian/JV 做互斥匹配；\(10\times10\) 的矩阵在现代 CPU 上是微秒到毫秒级，完全能满足实时性。

2. **若 \(m>n\)（例如拦截弹多于威胁）**：互斥不可行。应改用“覆盖 + 容量”模型：每个威胁至少 1 个拦截弹，额外拦截弹作为备份/补射；用最小费用流或两阶段（覆盖匹配 + 贪心补位）实现。

3. **若要把分配层放进策略网络做端到端训练**：Hungarian 不可微，改用 Sinkhorn / Gumbel-Sinkhorn；训练时用软分配，部署时再舍入成 \(b\)。若只是推理后处理，直接用 Hungarian 更简单、更精确。

4. **若要分布式/无中心**：优先分布式拍卖（有 \(\varepsilon\)-最优保证、anytime）；若任务带边际收益递减/动态增删，选 CBBA；若必须可微，选 gossip Sinkhorn。

5. **动态场景**（目标被击毁、新目标出现）：优先可热启动/anytime 的方法（增量 Hungarian、拍卖、CBBA），避免每步从头求解。

6. **评测与复现**：若将这些算法作为对比 baseline 落地到代码，需遵守仓库的《对比算法构建代码规范》，对齐环境、动作空间、观测、评测协议，并记录超参、种子、checkpoint 与试次元数据。

一个实用的“混合方案”：

- 先用 Sinkhorn（少量迭代）得到软分配和近似对偶价格；
- 用贪心舍入得到可行 \(b\)；
- 若还有时间预算，用 2-opt 或对少数冲突做局部 Hungarian 精修；
- 这样在 GPU/批处理、实时性和最优性之间取得折中。

## 7. 关键伪代码

### 7.1 非互斥 argmax

```text
for i in 1..m:
    b[i] = argmax_j S[i][j]      # 平局按二级准则
```

### 7.2 互斥贪心

```text
L = 按 S_ij 降序排列的所有 (i, j)
for (i, j) in L:
    if i 未分配 and j 未被占用:
        分配 i -> j
```

### 7.3 拍卖（单轮 \(\varepsilon\)-CS）

```text
p[1..n] = 0
while 存在未分配智能体:
    i = 任取一个未分配智能体
    j1 = argmax_j (S[i][j] - p[j])
    j2 = argmax_{j != j1} (S[i][j] - p[j])
    delta = (S[i][j1] - p[j1]) - (S[i][j2] - p[j2]) + epsilon
    p[j1] += delta
    若 j1 已被 k 占用: 取消 k 的分配
    分配 i -> j1
```

外层再做 \(\varepsilon\)-scaling：从大 \(\varepsilon\) 开始，逐步减半，每轮用上一轮价格热启动。

### 7.4 Sinkhorn + 舍入

```text
K = exp(S / tau)
v = ones(n)
repeat:
    u = 1 / (K @ v)
    v = 1 / (K.T @ u)
until 收敛
P = diag(u) @ K @ diag(v)
b = round_to_assignment(P)      # 贪心舍入，或对 P 再跑 Hungarian
```

## 8. 动态场景：触发时机与两阶段分配（本项目）

### 8.1 触发条件：按“波次”而不是每步调用

建议把一次分配绑定到一个“静默窗口”（没有在飞导弹、所有目标未被占用）：

状态量：

- \(L(t)\)：在飞/未解除的导弹数（由共享的发射信息可得）；
- \(o_j(t)\)：目标 \(j\) 是否被在飞导弹占用；
- `roster_version`：存活智能体/目标集合的版本号；
- `assignment_valid`、`dirty`。

状态机：

```text
if L > 0:
    assignment_valid = False
    if roster changed: dirty = True
else:
    if (not assignment_valid) or dirty:
        run_assignment()
        assignment_valid = True
        dirty = False
```

- 回合开始 \(L=0\)、`assignment_valid=False`：首次调用。
- 第一枚导弹发射后 \(L>0\)：不重算；直到所有在飞导弹解除、\(L\) 回到 0，下一波次重算。
- 目标出现/被毁、智能体死亡/新增：若 \(L=0\) 立即置 `dirty` 并重算；若 \(L>0\) 只置 `dirty`，等回到 0。
- 用 `assignment_valid` 锁避免在 \(L=0\) 的每一步重复调用；一次静默窗口只算一次。
- 若长时间不开火但距离变化很大，可加“最小重算间隔”或“距离变化阈值”；默认不建议频繁重算，避免目标抖动。
- 如果你说的“已发射导弹为 0”是指“累计发射数为 0”，那就只在回合开始触发；若指“在飞/未解除数为 0”，则按波次触发。推荐后者，否则后续波次仍可能撞车。

分布式触发：每个智能体从共享发射信息计算 \(L\)，用 max-consensus 或版本号/epoch 达成一致；有中心节点时由中心广播 `assignment_epoch` 最简单。

### 8.2 \(m\le n\)：直接矩形 Hungarian，不要先按平均距离筛目标

目标实际是：每个智能体一个目标、目标互斥、覆盖数最大（= \(m\)）、总距离最小。这正是 \(m\times n\) 矩形 LAP：

\[
\min_A \sum_{i,j}D_{ij}A_{ij}
\quad\text{s.t.}\quad
\sum_j A_{ij}=1,\ \sum_i A_{ij}\le1.
\]

直接对 \(D\) 跑 `linear_sum_assignment` 即可；它会自动选出要覆盖的 \(m\) 个目标并给出最优匹配。

“先按平均距离排序取 \(m\) 个目标”只是启发式，可能把“对某个智能体很近、但对其他人很远”的目标排除掉。反例：\(m=2,n=3\)，距离

- 智能体 1：\(A=1,B=2,C=3\)
- 智能体 2：\(A=100,B=2,C=3\)

平均距离：\(A=50.5,B=2,C=3\)，按平均会选 \(B,C\)，总距离 \(2+3=5\)；最优是 \(A,B\)，总距离 \(1+2=3\)。因此直接用矩形 Hungarian 更稳。

若还要考虑威胁优先级，把代价改成 \(C_{ij}=D_{ij}-\lambda w_j\)（\(w_j\) 为目标威胁权重），仍是 LAP；但“覆盖数”在行和 \(=1\)、列和 \(\le1\) 下始终是 \(m\)，权重只决定选哪 \(m\) 个。

### 8.3 \(m>n\)：转置 Hungarian 覆盖全部目标，剩余 argmax

目标：\(n\) 个目标全部覆盖（最大覆盖 \(=n\)），并让这 \(n\) 个“主攻”智能体的总距离最小。把矩阵转置：目标为行、智能体为列，

\[
\min_A \sum_{i,j}D_{ij}A_{ij}
\quad\text{s.t.}\quad
\sum_i A_{ij}=1\ (\forall j),\ \sum_j A_{ij}\le1\ (\forall i),
\]

即对 \(D^\top\)（\(n\times m\)）跑 Hungarian。它会自动选出最合适的 \(n\) 个智能体，并保证每个目标恰好一个主攻；不需要先按“到敌机平均距离”筛 \(n\) 个智能体。

平均距离预选同样可能次优。反例：\(n=2,m=3\)，目标是 \(A,B\)：

- 智能体 1：\(A=1,B=100\)
- 智能体 2：\(A=100,B=1\)
- 智能体 3：\(A=50,B=50\)

平均距离：\(A\approx50.3,B\approx50.3\)，若按平均选中 1、3，总距离约 \(1+50=51\)；最优选 1、2，总距离 2。

剩余 \(m-n\) 个智能体再 argmax。这里必须明确 argmax 的打分：

- 用网络倾向 \(S\)：\(b_i=\arg\max_j S_{ij}\)，允许重复覆盖（作为补射/备份）；
- 用距离：\(b_i=\arg\min_j D_{ij}\)，即“就近补位”；
- 若希望剩余智能体也不要重复，则它们应空闲或进入容量约束，这和“argmax”语义冲突，需要单独定义。

如果希望“覆盖全部目标 + 所有智能体（含剩余）总距离最小”，则不要用两阶段，直接用带下界的最小费用流：

\[
\min \sum_{ij}D_{ij}A_{ij}
\quad\text{s.t.}\quad
\sum_j A_{ij}=1,\ 
\sum_i A_{ij}\ge1,\ 
\sum_i A_{ij}\le c_j,
\]

其中下界 1 保证覆盖，\(c_j\) 可取 \(m\)（允许补射）。这是多项式精确解；但若剩余智能体的真实目标是“按 \(S\) 打分”而不是距离，则两阶段更符合语义。

### 8.4 分配结果必须“锁住”，否则 argmax 会再次撞车

只在触发时刻算一次不够；如果下一步每个智能体仍按自己的 argmax 选目标，交叉会立刻回来。需要：

1. **动作屏蔽**：把非分配目标的 logits/概率置为 \(-\infty\)（或 softmax 后 mask），只允许选中/保持分配目标；若允许“不开火”，保留 no-fire 动作。
2. **状态增强**：把 `assigned_target`（one-hot）、`assignment_epoch`、`assignment_valid` 加进观测，否则网络不知道协调结果，容易与 mask 冲突。
3. **目标锁**：从本次分配生效到第一枚导弹发射（或本波次结束）保持目标不变；目标被毁/智能体死亡时按 8.1 的触发条件重算。
4. **训练一致性**：若策略已在无 mask 的 argmax 下训练，直接加硬 mask 会带来分布偏移；可用 mask 微调，或把分配作为环境/动作约束的一部分（MAPPO 的 on-policy 训练可以承受硬 mask）。

### 8.5 实现片段（scipy）

```python
from scipy.optimize import linear_sum_assignment
import numpy as np

# D: m x n 距离/代价矩阵，行=智能体，列=目标
if m <= n:
    rows, cols = linear_sum_assignment(D)          # m 个智能体 -> m 个不同目标
    assign = {int(i): int(j) for i, j in zip(rows, cols)}
    extra = []
else:
    trows, acols = linear_sum_assignment(D.T)      # 目标 -> 智能体，覆盖所有目标
    assign = {int(a): int(t) for t, a in zip(trows, acols)}
    matched_agents = set(assign.keys())
    extra = [i for i in range(m) if i not in matched_agents]
    for i in extra:
        assign[i] = int(np.argmax(S[i]))           # 或 argmin D[i]
```

注意 `linear_sum_assignment` 在平局时的选择可能依赖实现；若要严格可复现，给 \(D\) 加极小的确定性扰动或使用字典序规则。

### 8.6 边界情况

- \(m=n\)：两种写法等价，都是一对一置换。
- 目标被击毁/新目标出现：更新 `roster_version`，在 \(L=0\) 时重算；若 \(L>0\) 延后到下一波。
- 智能体死亡：从 \(D\) 中移除该行，重算；剩余智能体可能变成 \(m<n\) 或 \(m>n\)。
- 存在不可达目标：把 \(D_{ij}\) 设为 \(+M\) 或删除该边；Hungarian 仍可处理（尽量不选）。
- 路径距离与直线距离不同：若用路径规划距离，确保所有对都有可行路径；不可达用大代价。
- “交叉”若是轨迹交叉而非目标冲突：仅最小化距离和不一定消除轨迹交叉，可加转向角/路径交叉惩罚，或用 Hungarian 后再做 2-opt/轨迹平滑。
